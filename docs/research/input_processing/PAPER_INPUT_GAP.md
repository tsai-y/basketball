「裁切後縮放」不足以推出必須先偵測投籃起訖。論文TSCI三分支是特徵維度的交互機制，不是將輸入分成球員、球、籃框三種影片；見[§2.3](https://www.frontiersin.org/journals/neurorobotics/articles/10.3389/fnbot.2024.1471327/full)。這兩點都不能作為另開事件裁切工作的依據。

25FPS在這裡是資料描述；50幀是輸入長度。不能據此聲稱50幀必須只涵蓋2秒。當前整段均勻抽樣是已凍結的專案假設，不是已驗證的作者算法。

## 程式接線核對：現在缺的是什麼

- [凍結契約](../specs/input_foundation_v1.json)及[FoundationDataset](../../../development/aca_eight_class_data_v1/foundation.py)已提供張量、`class_id`、`binary_label`與來源資訊。
- [舊train.py](../../../development/aca_net_v1/train.py)第28、330–331行仍使用 `Basketball50Dataset`；第289、363行仍以 `binary_label` 為目標。不能只把輸出頭改成8就稱為八類訓練接通。
- [model.py](../../../development/aca_net_v1/model.py)可接受 `num_classes`；這只表示介面容量，不代表八類loss、metrics、資料範圍與選模已一起驗收。本輪未建立模型。
- 64個基準檔案與51個歷史檔案SHA再次核對一致。既有8739支技術驗收直接沿用，沒有重跑。

本次八類任務是資料／介面目標；既有二類validation成績不轉寫成八類成績，也不與論文結果直接比高低。

## 單一下一步：凍結基準的八類資料／指標接線

下一個有限任務建議只補一個隔離的八類資料與指標adapter。它沿用已驗收的FoundationDataset，明確使用 `class_id`，輸出8類CE、8×8混淆矩陣與清楚定義的macro-F1。二類只作另外標明的衍生指標；必須指定是八類argmax後映射還是機率加總，不能混為同一算法。

完成條件：以小型人工可計算的CPU合成logits／labels確認類別順序、loss／混淆矩陣、二類映射與錯誤label拒絕，並確認資料契約仍是7192／1547。這是有限的介面驗收，不是增加影片抽樣或模型效果試驗。若發現必須修改凍結loader、切分或標籤才能接通，停止並提出具體問題。

本輪僅提出上述下一任務，未實作或執行測試。下一任務也不包含模型forward、optimizer、test或訓練啟動。實際訓練前仍須另行定稿架構與訓練規格；原有架構缺證不因資料接通而消失，沿用[既有架構核對](../ACA_RECONSTRUCTION_SPEC.md)，不重新展開模型搜尋。
