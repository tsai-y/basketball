## 4. Split、來源與test接觸界線

- 現有split seed為20260927；50個來源群組分為35 train、8 validation、7 test。v160/v166依既有重複證據合併。
- 20,000個候選assignment以影片數及二類Make數平衡選定，未使用模型分數；不是八類分層最佳化。本輪沒有重跑該搜尋。
- manifest中的source_group與已保存assignment相符，沒有群組跨train/validation/test；已知位元完全相同群組沒有多份同時保留。這不代表已排除所有轉碼近重複。
- source_group來自檔名v代碼，並未獨立核實每個代碼與真實比賽的一對一關係。因此稱「來源分組隔離」，不把它升格成已驗證的新比賽泛化。
- 作者80/10/10的精確ID、seed、分組與清理政策目前缺證；不能由比例反推原split，也不把本地70/15/15稱為論文相同協定。
- 本專案已保存歷史test評估。重分同一批影片不會恢復全專案未見狀態；本輪只讀manifest內test中繼資料，沒有讀逐片test預測或執行test。

原split取得不到時，可另立**明示假設的80/10/10重建切分**，但須事先決定來源分組與去重規則，並揭露歷史test接觸；原70/15/15與其已訓練結果保留。比例相同也不等於精確複刻。此為退出缺證的可行路徑，本輪沒有建立新split或選定新seed。

## 5. 取幀、FPS與空間前處理契約

現有來源：[data.py](../../development/aca_net_v1/data.py)。下列只是保存的實作定義，不是本輪選定的新八類配方。

| 項目 | 現有明確行為 | 八類契約尚需定案 |
| --- | --- | --- |
| 影片範圍 | 完整約6秒片段，可能含結果畫面 | 複刻定位為全片分類；不混稱離手前預測 |
| 時間 | `floor(i*(F-1)/49)`，i0..49，含首尾 | 作者時間抽樣／多clip或多view聚合未核實 |
| FPS | 使用原生解碼幀序，沒有轉25FPS | 舊紀錄23.976：7602支；29.97：2475支；25：234支。不能擅自認定作者曾如何轉碼 |
| 短片 | F<50拒絕；舊檢查F145–180 | 若資料版本變動需明訂處理，不從test失敗臨時改規則 |
| 空間 | 320×240全圖→160寬×120高，INTER_AREA，無crop | crop區域／演算法／train與eval差異缺證 |
| 色彩／正規化 | BGR轉RGB，float32/255，ImageNet V1 mean/std | 作者具體正規化版本未核實；不得靠多種組合追90%後再稱原版 |

論文宣稱25FPS與本地混合FPS是待解差異，不直接判定哪邊錯。均勻抽50張不等同「標準化到25FPS」；本輪也沒有轉碼、製作新clip或移動影片。

## 6. 一次模型、兩種任務的評估定義草案

1. 主任務：八類logits→argmax，exact tie取較小class ID；每影片一個最終預測。若未來採多view，聚合規則必須先固定。
2. 主指標：八類top-1 accuracy。另報8×8混淆矩陣（row真值、column預測）、各類support/recall及等權macro precision/recall/F1；zero denominator記0並保留support。
3. 次任務：`binary_prediction = class_to_binary[argmax_8(logits)]`，映射為`[0,1,0,1,0,1,0,1]`，真值也用同一映射。報二類accuracy、macro-F1、Miss/Make recall。模型只看RGB tensor，不把檔名、類別、v碼或比分OCR當特徵。
4. 選模提案：以每影片平均八類validation CE的嚴格最小值選checkpoint，平手較早輪；這是可驗收的專案規則，尚非作者評估程式核實結果。
5. 多類AUC的OvR/OvO、macro/micro/weighted與作者F1平均方式仍未核實；不把新定義的macro-F1直接當論文F1同規格。
6. 90%目標於訓練前固定評估集、樣本納入與映射規則；validation追蹤與最終test分別報告。達90%不是作者實作一致性的充分條件。

對相同樣本及上述top-1映射，八類正確必然二類正確，因此二類accuracy≥八類accuracy。本輪窮舉64種真值／預測標籤配對核對此邏輯；這是數學驗證，**不是模型新成績**。它不適用於先將四個Make機率相加再以0.5判斷的另一種規則，也不保證不同split或新比賽的表現。

現有trainer仍明確使用2類head、binary_label與2×2 Metrics，不能只改head為8類。等資料契約釋出後，八類adapter須在隔離的新版本驗證，保留原二類程式指紋；本輪沒有寫adapter或改訓練入口。
